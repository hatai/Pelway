# 決定後のメール下書き

状態: 失敗（機能なし）。main に決定後のメール下書き生成が無い。

## Sub-features

- 決定の確定をきっかけに、決まった案からハルが顧客宛てメールの下書きを作り、チャンネルに出す
- 下書きの保存（作られた下書きを API で読み直せること）

## How to get to it (user POV)

山本が案A を選んで決定を確定すると、ハルが #案件B に、決まった内容を書いたメールの下書きを投稿する。

## Driving it with verify-run

`verify-run --feature mail-draft`。`decision` と同じ段 1〜9 のあと、段 10 で 10 秒待ち、決定の前の最後の `seq` より後にハルの投稿があるかを `GET .../messages?after_seq=<seq>` で読む。応答は `steps/NN-messages-after-decide.resp`。

## Gotchas

- main の runner-lite は判断待ち（AwaitingDecision）で止まり、決定の後に何も投稿しない（`crates/pelway-runner/src/lib.rs` の冒頭のコメント「決定後のメール下書き生成は PR-3 で加える」）。下書き生成は Issue #330 の PR-3（PR #399）の範囲で、main には無い。そのため段 10 は「失敗（機能なし）」になる。待ち時間を延ばしたり段 10 を外したりして通したことにしない。
- 下書きの保存先（下書きを読み直す経路）も main には無い。機能が入ったら段 10 を次の確認に直す: 決定の前には下書きを作れないこと、決定の後にだけ作れること、作った下書きを API で取り直して中身（決まった案が書かれていること）を確かめること。
- メール下書きは、送信の経路をコードにも設定にも持たない。外部へのメール送信はこのスキルの対象外。
