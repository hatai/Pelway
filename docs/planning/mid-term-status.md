## 統合した変更と理由

| 入力・論点 | 対応 | 理由・残論点 |
|---|---|---|
| 原案の初月は準備中心 | W1〜2から条件付き面談、W2機能分解、W4 A〜C手順初版 | 相手の同意・人の時間があれば製品完成を待つ必要なし。実際の連絡は別承認 |
| 局所試作の3週と31日の不一致 | W3〜4は設計・工数分解、実装は31日以降かつ承認後 | 4週見積もりとの循環を避け、面談を優先する。技術の調整案に一致 |
| 局所試作とP1aの混同 | 合成・ローカル・固定応答・ダミーのみ。P1aで作り直し、合格結果は持ち越さない | Aは局所では試せずB/Cも一部。実LLM・VM・実連携の証拠ではない |
| プロダクト表の局所安全試験「対象外」 | 不採用。局所経路の試験を実施し、P1a全体試験の代用にはしない | 技術の20回/5回試験案と合わせる。安全免除と誤読させない |
| 局所試作のUI部品と技術の画面なし範囲 | 技術試作は画面なし、UIモック・仕様は別成果物。部品実装追加は別見積もり | 20〜40人時へ暗黙に画面工数を足さない |
| 最終月に安全・AA試験集中 | 機能と同時、各月末、最後の回帰へ分散。モックは61〜90日に事前検査 | 手戻りと再試験時間を確保する。事前確認だけでAA適合を宣言しない |
| 面談とUIを同じ回へ | 45分面談の末尾10分に含める。確認・再試験は別記録 | 二重加算は除くが実時間は消さない。4面談だけで5人試験を保証しない |
| UI1〜90日の確認3.5時間 | 項目和は3時間と明記、0.5時間差を確認待ちにする | 確認前に確定総数へ使わない |
| 技術20〜40人時 | 狭い実装の仮定としてのみ記載。準備・試験・修正等の包含を確認待ち | 総工数やP1a完成見込みにしない |
| 見積もり1.5倍で停止 | 上限延長として不採用。承認上限前の超過見込みで見直し、上限で停止 | 人の時間の追加許可を捏造しない。長期80%確認案は提案として維持 |
| ダークモード延期 | 未承認の代替案として残す。現行の長期P1a条件は維持 | 中期で長期条件を弱めない。外観の再設計をしない |
| 過去UI4〜6週＋約2週 | UIがbot側の期間と補足した事実を記録。人時に加えない | 長期本文は変えず、今後人時へ置換する |
| 月4〜6の全体工数 | 未見積もりを明示。180日完成保証なし | P1b/P2実施を範囲に入れない。安全境界は維持 |
