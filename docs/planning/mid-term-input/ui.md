## 2. 人の時間の合計（仮定）
- 1〜90日：U1〜U6で、確認が約3時間（U1〜U5の合計）、試験の実施が約80分（面談の内数）。試験は面談と同じ回に入れる前提です。面談と別の日にすると、段取りと移動で時間が増えます。
- P1a（91〜180日）：U7とU8は**未見積もり**です。必要な情報は、P1aで作る画面の数（プロダクト担当）、実装の担当者と週の稼働（濱田さん）、ダークモードを出すかどうか（下記）です。4週に人時の見積もりとして出し直します。
- 以前出した「画面設計4〜6週、決まりの正式化は別に約2週」は、bot側の作業期間の目安でした。人の工数ではないので、上の数字とは足しません。

## 3. 最初の2週間とその後の現実性
- 最初の2週間でUIがやることは、U1の設問だけです。人の時間は確認の約0.5時間で、現実的です。
- 31〜90日は、試験を面談に入れれば無理がありません。面談相手が集まらない場合、U3はP0の面談の遅れにそのまま連動します。面談相手以外を代わりに使う場合は、設計に関わっていない人間に限ります。botや設計担当は試験の参加者に数えません。
- 顧客検証と最小の技術試作を並行する案にも、UIから反対はありません。ただし試作で先に作るのは、状態表示の部品（U4）だけにします。U3の結果で呼び名が変わる可能性があるので、文字列は後から差し替えやすくします。
- AAの確認を151〜180日にまとめる案には反対です。最後にまとめると、不適合を直す時間が残りません。U6とU7のように前倒しします。

## 4. 濱田さんの判断が必要な点
- P1aでダークモードを出すか。ライト表示だけにすればU7とU8の作業は減ります。ただし、長期計画のP1a通過条件（群青のコントラスト修正）に関わるので、UIからは決めません。出す場合の修正値（暗い背景では#8F96FFを使う）は先に用意します。
