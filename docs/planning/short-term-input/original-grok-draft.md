# Pelwayの短期目標案：最初の30日

2026-11-08（日本時間）作成。v0.1、Grok Bot案。チームレビュー・実行承認は未了。
基準は[長期v0.5](../long-term-milestones.md)と[中期v0.4](../mid-term-milestones.md)。T0は計画と投入時間を承認した日。以下はT0相対の提案で、暦日の納期ではありません。

## 最優先の到達目標

**30日で「誰の、どの1業務なら、人と役割付きAIが同じチャットで働く価値があるか」を、実例と反証から選ぶ。** 製品完成や資料の本数を目標にしません。

初月は少なくとも**2つの独立チームの実例**を聞く案を引き継ぎます。仕事の頻度、依頼→AIの作業→人の判断→引き継ぎ、現在の手戻り、既存チャット＋個人AIで足りない理由、Pelwayへの移行・案件単位の併用制約を残します。参加者数とチーム数は別に数えます。

月末に、①試す1業務と選定理由、②確認済み・反証・未確認の区別、③必要人時・費用の初版と不足、④継続・絞り直し・延期・中止の提案が揃えば、次の判断ができます。実例が足りなければ業務選定は仮説のまま。需要確認済み・P0通過とはしません。

### 最初の2週間は、この順で進める

- **1〜2日：** AIが候補業務2つと聞く質問を下書き。人は初月に使える時間と、聞けそうな相手・経路を確認する。対象は小規模ITチームの社外案件を仮説とし、決めつけない。
- **3〜7日：** 「最近実際に困った一件」から聞くガイドと匿名記録欄を整える。連絡文は宛先・経路・本文を揃えた下書きまで。参加・記録・保存／削除の条件も用意する。
- **8〜14日：** 個別の送信承認、参加・日時・記録同意、人の時間が揃えば人が面談する。揃わなければ準備と機能分解・公式仕様調査を進める。UI設問の未準備を理由に面談を止めず、理解試験は未実施と残す。

面談は一般的な課題を先に聞き、モックで答えを誘導しません。録音・顧客原文・画面共有は求めず、機密情報を集めません。状態名理解試験は中期の31〜60日の窓で扱い、初月の必達へ前倒ししません。

## 人とAIの分担・承認の境界

- **AIが支援できること：** 既存資料から仮説・質問・連絡文の下書き、機能分解、公式仕様の整理、匿名記録の比較、モック指示、見積もりと試験一覧の初稿。今すぐ進められるのは、外部連絡・新規支出を伴わない準備です。今回実施したのは本計画の作成だけです。
- **人が担うこと：** 投入時間と相手の選択、連絡・面談、同意確認、実例の妥当性確認、業務選定と継続判断。AIの作業時間を人の稼働枠に加算しません。各担当botへの依頼・合意は今回行っていません。
- **別承認が要ること：** 実際の募集・送信、支出・アカウント作成、実装・外部接続・データ利用。連絡は具体的な宛先・経路・内容を実施前に確認します。

## 時間が足りないとき・月末の判断

初月の総必要人時は未確定です。週15時間・初月45時間、市場15時間の4面談例は既存案の比較仮定で、承認済み容量ではありません。P0全体の約8人も初月必達にはしません。

優先順は**面談と記録 → 1業務の選定 → 危険経路の整理と見積もり → モックの作り込み**。不足ならモックの詳細化や調査の幅を縮小・延期し、未実施を隠さず、週次の未完了を持ち越します。募集不足は承認待ち・未到達・無返信・条件不適合・役割不足・日時不一致に分け、経路・説明・対象を一度見直します。人数不足だけで需要ゼロとはしません。見直しても独立チャットを試す理由がなければ、対象変更か延期・中止を提案します。

31日以降の局所試作は個別見積もり、人時上限、環境・安全経路の承認後だけ。総27〜54人時は技術仮定で、追加修正・UI実装は別です。面談の枠を先に取り、残りで収まらなければ延期します。実装を伴うP0-Tの安全検証を通過する前にP1aへ進まず、机上調査や局所試作を通過の代用にしません。

**直近の第一歩：** AIが比較できる候補業務を2つに整理する。その選択前に、濱田さんにはまず「最初の2週間に使える時間」と「話を聞けそうな相手・経路の有無」だけ確認する案です。支出は当面ゼロを推奨し、有料手段が必要な時点で相談します。T0・初月全体の容量・担当・予算は未確定のまま明示します。
