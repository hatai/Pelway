# 06 日本語・英語の共通資源

初版から日英の両方を対象にする。翻訳資源はFluent `.ftl`、キーは `task-state-working` のような安定IDとする。RustとJavaScriptのformat adapterから同じ資源を読む。enum名をそのまま利用者へ表示しない。

`pelway-domain` は状態とイベントschemaを定義する。翻訳内容と状態の意味を区別し、片方の言語だけで意味を増やさない。WebのIntlとRustのICU系formatterは日付・複数形・数値のfixtureを共有し、比較するbrowser/ICU/CLDRの版と差異を記録して固定する。翻訳資源やfontを実行時に外部CDNへ取りに行かない。

<a id="ch06-s02"></a>
## 表示と入力の規則

- 初期言語はOS/browserを参考にし、利用者の設定で日英を切替。再起動なしの切替を設計する。翻訳なしのキーを画面へ露出させず、build時に不足を検出する。
- 保存時刻はUTCとし、ローカル試作の期限・受付・経過表示はJSTの絶対日時に残日数を添える。将来の利用者timezone切替とは分ける。監査APIはUTC offsetを保持する。言語とtimezoneは独立。
- 英文を文字数の増減だけで切り詰めず、複数形と埋込変数をFluentの機能で表す。文を部品ごとに連結しない。
- CJK禁則、和英混在、絵文字のgrapheme、RTL入力、コードの等幅と長URLを試す。自動翻訳・外部spellcheckは本体機能に含めない。
- IME変換中のEnterは送信にしない。composition開始/終了とキーイベントを各OSで試す。候補窓がcaretへ追随し、focus移動で文字を落とさない。
- 読み上げの名前は表示名・主体の種類（人／Bot／外部エージェント／外部ツール）・状態を含める。外部主体では連携名も読み上げる。重複eventのlive announcementは一度だけ。

コピーの初期提案は、通常の範囲選択では選択本文をコピーし、構造化された「会話をコピー」では送信者・4種類の主体ラベル・時刻を含める。両UIで同じfixtureを使う。複数メッセージにまたがる選択は実機で未確認。クリップボード同期による持出しは10の未保証境界。

<a id="ch06-s03"></a>
## 配布前の試験条件

日英双方でログイン、チャンネル、メンション入力、9状態、承認snapshot、差分、失敗理由、連携有効化の国外可能性表示を試す。200%拡大と高コントラスト、NVDA/VoiceOver/Orcaの結果を別々に記録する。WCAG 2.2 AAを目標にするが、AccessKitを組み込んだだけで適合とは言わない。

フォントは同梱を推奨する。Noto Sans JP等の具体的な配布ファイルとライセンス、CJK fallback、emojiのOS利用と同梱条件を実装前に確認する。UIの外観・配色は変更しない。

<a id="ch06-s04"></a>
## 状態の理由と責任分界の翻訳

状態名だけでなく理由と境界表示も安定IDへ対応させる。表示案は03の理由表、共通表示契約は11を正とする。サービス名を翻訳キーの条件分岐にせず、連携定義とPlacementPolicyから文言を選ぶ。外部由来本文の文字列を認可/承認のボタンに使わない。

日英両方で、有効中連携の一覧/主体表示に「国内限定の外」の文字、外部本文/logに「外部由来・未確認」の帯、4主体の文字ラベルがあることを確かめる。本体の画面に「国内で完結」「準拠」「適合」を表示しない。翻訳不足/読み上げ/高コントラストでも境界を失わない。

操作の種類（04のcustomer_send／agent_handoff／tool_read／tool_writeに対応する日本語（顧客送信／外部への受け渡し／ツール読み取り／ツール更新））も翻訳キーにする。送信承認待ち/送信中のラベルと判断待ち一覧へ操作の種類/連携名を渡し、種類で見分け/並び替えできるようにする。種類はActionSnapshotの固定値から取り、外部本文から推測しない。

<a id="ch06-s05"></a>
## 取消・削除・サポートの表示契約

内部開始受理だけで「送信済み」にしない。取消受付、未開始抑止、外部停止要求、停止確認、操作結果の件数と証拠を分ける。結果不明は即時の判断待ちと経過時間を出す。24時間は昇格の期限であって初回表示までの待ち時間ではない。

期限はJSTの絶対日時と残日数、7日未満の現権限内強調。容量は80%警告と100%超過の保存前拒否を表示する。95%停止は採用しない。

削除はオンライン/索引/メモリ/端末/backup/外部先の確認範囲を別表示する。backupの14日は復旧対象の上限で、物理消去確認は別。未同期端末を含め一括完了にしない。24時間削除、有人応答時間は保証文にしない。有人枠を本人が受諾するまでは「有人対応の時間帯は未確定」とする。全表示の値は[13](13-operational-defaults.md)から参照し、日英で意味を一致させる。外観は変更しない。

<a id="ch06-notices"></a>
## 状況文言の安定ID案

意味は既存方針を継承する。識別子と英訳は文書上の案で実装済みではない。非同意者を名指しせず、「同意」のみを根拠にする表現にも固定しない。

| ID案 | 日本語 | 英語案 |
|---|---|---|
| notice-consented-scope-only | 許可された範囲だけを参照しました。 | Only authorized sources were used. |
| notice-deletion-accepted | 削除を受け付けました。対象の利用停止を先に処理し、確認できた状態を表示します。 | Deletion request received. We will restrict use first and show the status we can verify. |
| notice-support-hours-unset | 受付済み。有人対応の時間帯は未確定です。 | Request received. Staffed support hours have not been confirmed. |
| notice-outcome-unknown-24h | 結果を確認中です。再実行はしていません。 | The result is still being checked. The action has not been retried. |

取消表示キーは03を正本として日英を同期する。reason-cancel-acceptedは受付集約、reason-cancel-accepted-pendingは未確定件数付き集約、reason-cancel-after-startは個別送信、reason-stop-confirmingは外部runの停止要求済み/結果確認中に限定する。開始は内部受理であると説明し、物理送出済みへ読み替えない。新しいTaskStateは増やさない。

<a id="ch06-s06"></a>
## 情報取扱いの追加表示キー

| 安定ID | 日本語 | English |
|---|---|---|
| integration-connected-no-business-data | 接続済み · 業務データは未送信 | Connected · No business data sent |
| notice-ai-input-excluded | 一部の発言を除外して処理しました（利用の同意を確認できない範囲） | Some messages were excluded (consent for this use could not be confirmed) |
| state-use-stopped | 利用停止中（削除は未完了） | Use stopped (deletion not yet complete) |
| state-deletion-in-progress | 削除処理中（受付 {datetime} JST） | Deletion in progress (requested {datetime} JST) |
| state-deletion-completed | 削除完了（オンライン・索引・メモリ・端末で確認済み） | Deletion completed (verified for online data, index, memory, and devices) |
| state-deletion-backup-note | バックアップの復旧可能期間は作成から最大{backup_days}日です。復旧対象からの除外と物理消去の確認状況を分けて表示します。 | Backups are restorable for up to {backup_days} days from creation. Restore exclusion and confirmed physical deletion are shown separately. |

上記の削除完了は表示したオンライン等の全証拠が揃う場合だけ使う。未同期端末が残れば使わず、backupと外部先の残存を同時に区別する。{backup_days}は13の設定値14を差し込み、24時間の内部削除目標は画面に出さない。通知名/件数/未同意者から存在を漏らさず、現在の閲覧権限を検査する。

notice-ai-input-excludedは、除外元の存在を知る現在の権限を持つ出力先に、同意不足で除外した場合だけ使う。存在を知らせられない出力先にはnotice-consented-scope-onlyを使うか出力保留とし、氏名/件数からの推知を防ぐ。他の有効な利用根拠を確認して許可した処理を、同意不足として表示しない。送信行の4区分は03のsend-row-not-started/sent/unknownとreason-cancel-after-startを正本とし、外部run行のreason-stop-confirmingとは分ける。
