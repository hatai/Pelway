# 運用初期仕様 v0.1 採否記録

2026-11-09 JST。設計・運用値の選定記録であり、全員の最終賛同や実行承認ではない。対応先は[運用初期仕様](operational-defaults-v0.1.md)。元のv0.2/凍結文書は変更しない。

## 1. 入力と改訂の扱い

事業チーム（製品・技術・UI）とプロ会議（財務・営業・法務）の入力を使用。市場担当からの調査入力はなし。[技術入力](../../reviews/technical-operational-defaults-input-2026-11-09.md)の原ファイルには旧案が残るため、後続の部屋発言による撤回・修正を優先する。市場の他社比較は製品の法定値や実測値ではなく、今回の決定を待たせる必須条件にはしない。市場担当は企画の「新規調査不要」の指示に従い、着手していた競合保持/backup比較を途中で中止したと確認した。市場の調査入力はなく、未着資料の到着待ちではない。競合の既定値を根拠とする採用値はない。営業からの比較意見は市場担当の調査成果と混同せず、採用値は長期価値・運用負担・最小化の仮定で選定した。

主な後続修正は、財務のメモリ180日案撤回→最長365日、法務も最長365日を支持、技術の確認365日案撤回→製品の180日確認/30日保留を支持、技術の期限切れ未開始判定撤回、UIの7日前通知を製品周期に読み替え、Grok Botの即時判断待ち/役割候補化。以下はそれらを踏まえて企画が選んだ値で、撤回前の賛否と混同しない。

| 法定/例外 | 方法別の暦年1/3年と起算点を一次資料で確認。通常利用から隔離、必要な項目だけ | 同意証拠を任意365日で先に消さない。未分類を一律3年保存だけで有効化しない。法定必要期間を製品設定として任意選択しない |

本文等の日数/容量と、24時間削除/人の返信時間の内部目標は区別した。S1、鍵/復旧、実装/合成試験は未検証。弁護士確認と当事者等の具体的当てはめも未完だが、これを理由に数値決定や合成設計全体を止めない。

## 3. Codex/Claudeへの相談と採否

既存の相談経路へ仕様のみを渡した初回相談と、統合案の致命的差分に限った最終確認を実施。追加の全体レビューは行わない。いずれも静的な助言で、法務の有資格確認、実装、実測、全員の最終賛同を代替しない。回答原文は同フォルダのoperational-consultations以下に保存。

### Codex 初回

[回答](operational-consultations/codex-operations-v0.1.md)の8点を次のように扱った。

1. 全派生物を最短source期限に従属：採用、§2/R01〜03。
2. 別領域/物理空き/同時予約も容量管理：採用、C01〜08。数値は企画仮定で実測ではない。
3. task未終了を理由に画像/checkpointを無期限保存しない：原則採用。提案の各30日ではなく、既存の終了後7/30日を残し作成から37/60日の絶対上限を加えた。
4. 結果不明の抑止記録を消さず古いIDを新規に扱わない：採用、R16/§6。通常の配送metadataとは分離。
5. 有限再試行/恒久エラー即要対応：採用。提案の6再試行ではなく技術の5再試行を使い、通知段階を確定。
6. 5秒は内部開始受理まで、取消と受理の一意順序、根拠失効を別制御：採用、§6。物理送出前の競合ゼロを主張しない。
7. 読取照会を15分まで、24時間状況通知を人の対応から分離：原則採用。1/5/15分案でなく0/5/15分。24時間はACL確認したアプリ内表示のみで、メール/外部投稿の自動送信許可にはしない。
8. 法定保全の例外で本文の通常利用まで延長しない：採用、§2/§8。

### Claude 初回

[回答](operational-consultations/claude-operations-v0.1.md)の8点を次のように扱った。

1. 未解決dedupeを日数だけで消さない/90日点検：採用、R16。以後30日点検。
2. 無活動30日停止/作成365日task上限：採用、R07。未解決の外部操作は別管理。
3. 物理空き25%警告/15%停止/安全reserve：採用し、1GiB絶対下限と実volumeごとの測定を加えた。
4. 5秒内部窓と0/5/15分読取照会：採用、X01/X04。
5. 24時間状況表示は有人時間と別：アプリ内表示に限定して採用。外部の自動送信は採用しない。
6. 法的分類不明な記録を仮に最長3年へ：不採用。該当性・方式・起算点は別問題で、不明な機能を長期保存だけで有効化しない。既発生の必要最小記録は隔離保全。
7. 別の間隔/回数の削除再試行：有限化と失敗通知は採用、数値は技術案へ統一。
8. 実在の責任担当/代替/審査者：採用。ただし未確保の独立審査者を合成設計全体の停止理由にせず、緊急本文アクセスを非提供とする。

回答の要約で生promptと24時間/7日/30日の作業分類が混同される箇所は採用しない。生prompt/response/cacheの永続保存は0で、file/作業画像/checkpointだけが別分類の期限を持つ。

## 5. 納品直後の共有訂正（2026-11-09 JST）

- 市場担当が新規調査不要の指示で比較作業を中止済みと確認。「入力あり」「未着・到着待ち」はいずれも使わず、市場調査入力なしと訂正。新規調査や再開の依頼はしない。
- 技術担当は5秒を支持したが、「発行から送信呼出し開始まで」という条件は本仕様の内部開始受理と同一ではない。採用済みの5秒は内部開始受理までで変更しない。物理送出の最終検査・根拠失効・取消の境界は§6のまま。発行/受理/送出を同じ時点とみなさない。
- 技術担当の容量縮小への賛同を記録する。ただし最新発言の10GBと採用済み10GiBは単位が違い、完全な数値賛同とはしない。80%/95%通知案も追加採用せず、80%警告・100%超過の予約拒否を維持。
- 技術の14日推奨と削除/制限記録90日以上は採用済み仕様と整合する。今回の共有で30日に変更しない。UIは採用設定から日数を差し込み、14日を復旧対象の上限として表示し、物理消去の確認は別表示。オンライン削除24時間は内部目標であって対外保証表示にしない。

本追記は入力の出所/後続意見の訂正のみで、決定値・未完条件・実外部I/O無効を変更しない。
