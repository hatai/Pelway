# UI担当からの入力（長期マイルストーン用）

作成日：2026-11-08（日本時間）。担当は業務アプリUIデザインのプロです。この文書の項目はすべて**提案**です。工数は私の見積もりで、実績ではありません。

前提：現在の方針は `/workspace/pelway-public-docs/publish/` の公開版 brand-ui にあります。wiki と外向けQ&Aの自動生成は範囲外です。画面の見た目は UI担当だけが判断します。

| 段階 | UIの成果物 | 通過条件（達成） | 見直し・中止の条件 | 濱田さんの判断が必要な点 |
|---|---|---|---|---|
| 顧客検証 | 状態の名前と、架空のチームを使った画面の例 | 5人前後に見せて、説明がなくても「判断待ち／送信済み · 顧客回答待ち／結果不明」の意味が通じる | 半分以上が読み違えたら、状態の呼び名から見直す | なし |
| MVP | 主な画面（チャンネル、判断待ち、承認、作業を見る）と、デザインの決まりの初版 | 主な画面で WCAG 2.2 AA の要件を満たす（コントラスト、キーボード操作、フォーカスの表示、押せる部分は24px以上、状態を色だけで伝えない）。ダークモードで群青のコントラストが足りない問題（2.74）を解決している | AAを満たせない画面が残ったら、その画面は試験導入に出さない | 配色を正式に決めるかどうか |
| 試験導入 | 結果不明からの再開と、承認のやり直しの画面 | 人が迷わずに判断できる。判断待ちが放置された時間の中央値を計測している。合格ラインは試験導入の前に決める | 「結果不明」で誤って再送する操作が1件でも起きたら、その画面を止めて直す | 合格ラインの数値 |
| 有償化の前 | デザインの決まりの正式版（色、書体、角丸、部品） | 和文書体のライセンスを確認済み。ロゴの使い方の決まりを確定している | なし | ロゴの商標確認（費用と時期） |
| 拡張（Rustデスクトップ版） | デスクトップ版の画面方針 | ブラウザ版と同じデザインの決まりで作れることを確認してから着手する | なし | 着手の時期 |

工数の仮定：
- MVPまでの画面設計に4〜6週間。
- デザインの決まりを正式にまとめるのに、別に約2週間。
- いずれも、UI担当1人が決まりの作成と画面の確認を受け持つ前提です。

直近30／60／90日に優先すること：
- **30日**：状態の名前と画面の例を、顧客検証に使える形にする。
- **60日**：ダークモードのコントラストを直し、デザインの決まりの初版を作る。
- **90日**：MVPの主な画面について、AAの要件を確認する。
