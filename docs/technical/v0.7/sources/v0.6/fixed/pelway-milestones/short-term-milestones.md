## まず目指すことと、最初の2週間

**初月は製品ではなく、「誰の、どの1業務を試すべきか」を実例と反証で判断する。** 資料の本数、面談人数、試作の完成は目的にしない。別会社または別の指揮系統の2独立チームから、それぞれ直近の実例を1件以上聞く案を引き継ぐ。同じチームの2人は1チームと数える。届かなければ選定は仮説のままとし、需要確認済み・P0通過とはしない。

- **1〜2日：** 市場・プロダクトbotが最大2候補の困り事、既存手段との差、見送り条件と質問を下書き。技術botは調査計画を下書き。人による成果物レビューはこの窓には配分しないが、T0承認・時間や相手の判断まで0時間とする意味ではない。
- **3〜7日：** 人が面談ガイド・対象・経路を確認し、仮説と技術調査計画を確認する。人の確認は担当仮定を足して4時間。募集文は宛先・経路・内容を揃えた下書きまで。実行前の承認・参加同意・記録範囲を準備する。
- **8〜14日：** 個別の送信承認、参加・日時・記録同意、人の枠が揃えば人が面談する。揃わなければ未開催理由を残す。面談と独立に機能分解表、連携先の公式仕様比較、状態名の設問と正答を準備する。UI未準備で面談は止めず、初月は状態名試験を行わない。

## 1. 1業務を選ぶために残す証拠

最初の対象は小規模ITチームの社外案件を仮説とし、候補業務の中身はW1で比較するまで確定しない。一般質問を先に聞き、画面や状態名で課題を誘導しない。

市場の最小質問は、①直近いつ誰がどの道具で行った一件か、②どこで詰まり漏れや手戻りが起き何で補ったか、③既存チャットと別チャットを併用する条件は何か、④費用と試用の許可を決める人は誰か、⑤次の確認に協力できるか。プロダクトの質問は3つ以内に統合し、別面談を増やさない。

今回の候補の選定材料として、2独立チームの実例から、外部向け送信物の事前承認、交代・失敗による手戻りや二重送信、今の道具で承認待ちを追う負担を確認する。感想だけを証拠にしない。承認不要・一人で完結、既存手段で困らない、外部送信がない、という反証は隠さず残す。同種の反証が2チームにあればその候補は見送る案とし、独立チャット全体に需要がないとは一般化しない。

面談未開催、実例1チーム、反証が1件だけなど判断材料が不足・混在する場合は選定を仮説として残す。2チーム到達だけで需要や事業成立が証明されたとはしない。移行・併用では情報の持出し、権限、受渡し、必要許可、二重入力を確認し、単に「使えそう」では済ませない。

記録には、チーム識別子・利用者/購入判断者の役割・業務頻度・直近の流れと詰まり・現行手段・反証・移行/併用条件・未確認事項を残す。支払意思、購入判断者の確認、協力同意、契約、入金は別欄にし、回答を契約・支払実績に置き換えない。録音、顧客原文、画面共有は求めず、機密や連絡先を集計・試作に持ち込まない。

### 調査・表示で変えないこと

業務がメールを使わない場合、W2の比較対象はその業務の連携先へ切り替える。ただし調査対象の変更であり、長期・中期のメール連携を含むP1a条件を書き換える承認ではない。選定業務との不整合が残れば、次段階前に計画変更の要否を別に判断する。公開資料の読み取りと、実サービスの登録・API接続・送信実験を区別する。

流れはプロダクト、表示の文言・色・印はUI担当。送信中に完了色やチェック印を出さず、結果不明に直接の再送ボタンを置かない。外観は変更しない。試験モックは製品とは別にし、既存 `/workspace/demo/flow/` を変更しない。この計画策定中にモックを実装・配置するものではない。

U1はW2を目標に、削らず30日までに確認する案。状態図が未確定ならU1/U2を止める。U1確認済み・U2未完ならUI準備は「縮小して完了」と記録できるが、U2と試験そのものを完了扱いしない。U1も未完なら未完了として持越し、31〜60日の試験開始を必要条件が揃うまで延期する。U2や流れの延期が31日以降の開始に影響しないとは保証しない。

上の「—」は当該の確認時間を配分していない印であり、その週に人の仕事が皆無という意味ではない。UIの面談ガイド確認やW4手順確認などは市場・企画のまとめと共有する前提。共有作業は一つの作業IDで実時間を計上し、未算定分を0とせず残す。市場とプロダクトのガイド確認が実際に同一作業なら重複を控除するが、根拠なく控除して容量に合わせない。

面談同席は、同じ人の同じ時間なら二重加算しない。別の人が同席するならその人時を追加する。未見積もりは、募集往復・日程調整・不参加、追加面談/同席、企画統合の人の確認、総括・T0等の判断、技術実装担当の追加確認、仕様変更時の再作業など。初月の総必要人時は未確定。週15時間や初月45時間は比較仮定のままで、今回の確約や余力計算に使わない。

## 4. 容量不足、反証、月末の判断

優先順は、面談と記録 → 1業務の選定材料 → 危険経路の整理と必要見積もり → モックの詳細化。既知部分だけでも承認枠に収まらなければ、未見積もりを隠して進めず縮小・延期を判断する。

| 担当 | 縮小・延期する順 | 残すものと停止条件 |
|---|---|---|
| 市場 | 競合再確認の幅→候補2つを1つへ→反証表の詳しさ | 面談記録・未開催理由・反証そのものは削らない。W1〜2は既存調査を使い、再確認はW4の差分一度。重大公式発表のみ必要範囲で前倒し |
| プロダクト | W3流れをW4へ→A〜C初版を31日以降へ | 仮説一覧/質問を優先。分解表未完なら技術見積もりも未完。A〜Cの適用一覧と局所試験基準が未確認なら局所試作開始を延期 |
| 技術 | W3設計をケース/期待値に限定→W2比較を2候補へ→W4を幅と部分原価再確認までへ | 環境手順や総原価等が省略なら未完と記録。個別見積もり・全範囲の上限・安全環境を確認できなければ31日以降の着手不可 |
| UI | U2を結果不明/送信中の2場面へ縮小、必要なら延期。U1は30日までに確認する案 | U1を削らないが、未完なら試験開始を延期。UI未準備でも面談は続ける。状態図未確定ならU1/U2停止 |

募集不足は承認待ち・未到達・無返信・条件不適合・役割不足・日時不一致に分ける。経路・説明・対象を一度見直し、前後の結果を混ぜず、通過条件を下げない。未達だけで需要ゼロとはしない。見直しても試す理由がないなら対象変更/延期/中止を濱田さんに提案する。

月末は、①1業務の提案と根拠または未選定、②確認済みの事実・反証・未確認、③人時/費用の初版と未見積もり、④継続・絞り直し・延期・中止の提案を揃える。未達でも現状と次の判断を正しく残すことを優先し、資料本数で成果を代替しない。PRD公開版の書換えやP0合格は宣言しない。

承認済み人時/費用の上限がある場合だけ、その値に対して使用状況を確認する。80%時点の残見積もり確認を引き継ぐ提案で、自動監視を設定したものではない。超過見込みで止め、上限で新規作業・支出を停止、再開は別承認。上限や担当未定のまま実行を開始しない。

## 5. 初月以降へ進む境界

局所試験は架空データ・仮LLM・ダミー受信先で状態/再承認/結果不明停止を試す案。A担当交代は試せず、B/Cも局所部分のみ。試験設計は応答断20回・再承認20回・権限取消各条件5回という中期の提案を維持する。これらを実施したという意味ではない。
