# 10 国内限定（AI周りとファイルの置き場所を日本国内に限り、国外へ送らない）

追加要件（2026-11-08、濱田さん）。既存文書は変えず、今回の設計の初期条件として扱う。**どれも未検証で、適合を保証しない。**

## 1. 前提と用語
- **国内設置ホスト**：開発・試験に使うPCが日本国内に物理的にあること（**前提。機材は未確認**）。
- 「**国内保存**」（データが国内の機器にある）と「**国外送信なし**」（処理・運用・サポート・診断・再試行も含め、国外へ1バイトも出ない）は別物。本書が目指すのは後者で、前者だけでは満たさない。
- **構築時**（依存crate・npm・コンテナイメージ・モデルの重み・OSカーネルの取得）と**実行時**（合成データ・将来の機密データを載せて動かす）を分ける。構築時の取得は国外のサーバーからになることが多いが、データを載せない。**実行時は外への出口を閉じる**。

## 2. 保存・処理場所の棚卸し

| データ・処理 | 置き場所（推奨） | 越境しうる経路 | 閉じ方 |
|---|---|---|---|
| チャット本文・添付 | ホストのPostgreSQLとローカルボリューム | OSのクラウド同期（OneDrive / iCloud Drive）の対象フォルダに置いた場合 | データの保存先は同期対象外の場所に固定（Windowsは WSL の中、macOSは `~/projects` 等で iCloud Drive 外）。同期の有無は利用者の端末管理の範囲で、製品だけでは保証できない |
| LLMの入力・出力 | ローカル推論のプロセス（コンテナ） | 外部LLM API、許可外への自動切替 | 外部LLMは無効。ゲートウェイは許可リスト以外へ切り替えない |
| 埋め込み・RAG | ローカルの埋め込みモデル＋pgvector | 外部の埋め込みAPI | 使わない |
| Botの記憶・手順ログ | PostgreSQL | なし（ローカル） | — |
| ツール実行 | サンドボックス・コンテナ | MCPサーバーが外部APIを呼ぶ、Web検索、URL取得、リダイレクト | サンドボックスは出口なし。ゲートウェイの許可リストは**実行時は空**。リダイレクトは追わない |
| 外部メール | （無効） | 宛先・配送経路が国外 | 国内限定モードでは**外部送信を無効**、ダミーメールのみ。宛先の国と配送経路を確認できない送信はしない（Grok Bot・企画係の指示）。既存PRDとの不整合として08に記録 |
| DB・キャッシュ | ホスト（コンテナのボリューム、クライアントのSQLite / IndexedDB） | ブラウザの同期機能 | 同期はブラウザ設定・端末管理の範囲 |
| ログ・監査 | ローカルファイル・DB | ログ転送サービス | 使わない |
| バックアップ | ホストに直接つないだ国内の記憶装置だけ | クラウドバックアップ | 使わない。OSのバックアップ機能の対象にするかは利用者の端末管理の範囲 |
| 障害報告・テレメトリ | なし（パニック時はローカルファイルに書く） | 依存ライブラリや開発ツールの自動送信 | 自動送信する部品を入れない。実装前に通信監視で確かめる |
| 依存の更新・モデル取得 | 構築時だけ、人が手動で | 実行中の自動更新 | アプリの自動更新は入れない。実行中のネットワークは閉じる |
| 開発ツール（Docker Desktop、IDE、OS） | ホスト | 更新確認・診断送信 | Pelwayのデータを載せる経路ではないが、送信内容は**要確認**。Docker Desktop の代わりにWSL内のPodman/Docker Engineを推奨 |
| 日本語入力・OSの翻訳・スペルチェック | 端末 | クラウド変換候補などで入力文字が外に出る可能性 | 製品では止められない。端末管理の範囲として境界に明記（UI入力 §7） |
| 国外の端末からのアクセス・持ち出し | — | 利用者が国外から開く、ファイルを持ち出す | 国内限定モードでは国外端末からの利用を許可しない設計。手動の持ち出しは製品だけでは完全に防げないので**未保証**とし、要件から除外したとは扱わない |

## 3. 外向き通信の既定拒否（設計）
1. **コンテナのネットワーク**：`app` と `sandbox` のネットワークは内部専用にし、外への経路を持たせない（Docker/Podman の internal ネットワーク相当。Apple container での設定方法は**要確認**）。
2. **DNS**：外部のDNSを引けないようにする。名前解決は内部のサービス名だけ。
3. **ゲートウェイの許可リスト**：宛先は「ホスト名＋IP範囲＋ポート＋確認した日付と一次資料」で登録。**実行時の初期値は空**。追加は濱田さんの承認事項。
4. **ホストのファイアウォール**：ネイティブGUIは `localhost` のバックエンドにだけつなぐ。ほかへの通信は監視で検出する（ホストのOS全体を遮断するのは利用者の端末管理の範囲）。
5. **未知の送信先・リダイレクト・自動切替・再試行**：どれも許可リストの照合を毎回通す。照合に失敗したら止める（`stopped`＋理由）。

## 4. 外部サービスの扱い
> 第3版の注記：利用者が選んで有効化する外部連携は、本体の国内限定とは切り分ける（`../technical.md` §6.7）。下の「無効」は本体の機能（外部LLM・検索・URL取得）に適用する。
- 外部LLM・外部MCP・検索・URL取得は、**推論・保管・運用アクセス・再委託・サポート経路まで国内**と一次資料と契約で確認できるまで**未承認・無効**。国内リージョンの指定だけでは適合としない。各社の確認は市場担当の調査（`research/existing-chat-and-agent-oss.md`）を待つ。
- 代わりはローカル推論。制約：外部の大きなモデルより品質が下がる見込み（**未評価**）、GPUかメモリの大きい機材が要る（**機材未確認・未測定**）、モデルの重みの容量が要る、モデルのライセンスは個別に確認。

## 5. 試験（実装前の要確認と、実装後の試験条件）
合成データだけで行う。P1bより前にも行い、実顧客データは先に入れない（プロダクト §8）。

| # | 試験 | 合格の条件（案） |
|---|---|---|
| D1 | 全試験を通しで動かす間、コンテナのネットワークとホストの通信を記録（pcap・ファイアウォールのログ） | 許可していない宛先への接続・DNS問い合わせが0件 |
| D2 | ローカル推論を止める | タスクが `stopped`＋理由になり、外部へ切り替わらない |
| D3 | ゲートウェイの再試行・タイムアウト・結果不明 | 再試行でも許可リスト外へ出ない。結果不明で自動再送0 |
| D4 | 許可外へのリダイレクトを返すダミーサーバー | リダイレクトを追わず止まる |
| D5 | アプリ・ランナーを故意に落とす | 障害報告の外部送信0、ローカルにだけ記録 |
| D6 | ネットワークを物理的に切った状態で起動・使用 | 画面が固まらず、フォント・絵文字が表示される（UI入力 §7） |
| D7 | 依存ライブラリ・開発ツールの通信の棚卸し | 実行時に通信する部品の一覧が空。見つかったら設定で止めるか採用しない |
| D8 | 外部メールの送信操作 | 国内限定モードでは操作できない（無効表示） |

## 6. 要件を足す前の推奨から変わったところ
1. LLM：「外部LLMは未決」→ **国内限定モードでは無効**。実行の既定をローカル推論にした。
2. 外向き通信：サンドボックスだけ遮断 → **全ネットワークを既定拒否、実行時の許可リストは空**。
3. 外部メール：送信ゲートウェイ経由で可 → **無効（ダミーのみ）**。
4. 自動更新・障害報告・リンクのプレビュー・外部フォント：入れない。
5. Windowsのコンテナ：Docker Desktop を第一に挙げていた → WSL内の Podman / Docker Engine を推奨。
