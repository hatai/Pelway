## 3. 残る必須修正

### T2-01（高）：最終検査とattempt開始を一つのtransactionで受理する（Codex V2-01、Claude V2-01を統合）

- 箇所：03:61〜63（手順5〜7）、04:20、01の仕事の往復の図。
- 問題：手順6の再検査と手順7の開始記録が別操作で、その間に失効・取消がcommitされると、失効後に送信が始まり得る。同じ開始要求が再送されると、外部I/Oが二度許される読み方も残る。
- 最小修正案（技術担当の推奨）：
  1. 手順6と7を一つのDB transactionにまとめる。そのtransactionの中で、承認・task・連携アカウントの行をロックし、現権限・取消・失効epoch・fence・承認hashを読み、予約行を `reserved → started` に条件付きで更新する（予約行のexpected epoch/version/approval_hashが一致したときだけ。0件更新なら外部を呼ばずに拒否を記録する）。
  2. 外部I/Oを始めてよいのは、この更新に成功し、そのcommitが永続化したと確認できた1つの実行だけ。重複した要求や、開始記録後の再起動では資格を取り直せない。commitの結果が不明なら送信せず照合へ進む。HTTPクライアントの自動再試行は無効にする。
  3. `dispatch_attempts` に検査時のepoch/version/fenceを保存する列を足す。
  4. 開始記録後、I/O直前の再確認はしない。その代わり、D11（取消と送信の競合試験）の期待値に「開始記録後の取消は送信撤回を保証しない」と明記する。理由：記録後に止めても「未送信」と言える根拠がDB側に残らず、結果不明が増えるだけだから。
- 「永続化」の具体的な設定（PostgreSQLのsynchronous_commitや同期レプリカの扱い）は実装前の確認事項でよい。非同期commitのままI/Oを許さないことだけを本文に書く。

### T2-02（高）：開始済み・結果不明の操作を編集で承認待ちへ戻さない（Codex V2-02）＋追加指示の承認（Claude V2-02）

- 箇所：03:51（承認後の編集）、11のIntegrationPort `resume` 行。
- 最小修正案：「承認後の編集は前承認を失効させ送信承認待ちへ戻す」を、attempt_started前の操作に限る。開始後は元のsnapshot・operation・試行結果を保持し、編集内容は後続案として別operationで保存する。元が結果不明なら後続案の送信も解決まで止める。
- 外部へ出る `resume` の追加指示は、既定で新しいActionSnapshotと送信承認を要する。未決として残すのは「承認を省略してよい条件」だけにする。

### T2-03（高）：backupからの復旧後は外部dispatchを止めて照合する（Codex V2-03）

- 箇所：03の固定承認と外部副作用、04の耐久化、08の障害注入。
- 最小修正案：過去のbackupへ戻したときは、外部dispatchを既定で停止する。復旧点より後に始まった可能性がある操作は、提供元の照会結果や別系統の記録で照合し、照合できないものは未実行と見なさず結果不明として人の判断に回す。DB障害とbackup巻き戻りを試験計画に足す。

### T2-04（中）：語彙と一意制約をそろえる（Claude V2-05、V2-06）

- `ActionSnapshot.action_kind` の列挙値を04で一つに固定する。案：`customer_send`（顧客送信）、`external_handoff`（外部への受け渡し）、`tool_read`（tool読取）、`tool_write`（tool更新）。06・11の表示名と翻訳キーはここから対応させ、11の「agent委任」は「外部への受け渡し」にそろえる。UI担当の「状態名の横に種類を出す」表示もこの値を使う。
- 04に `unique(workspace, approval_version_id)` を足す（承認版ごとに予約は一つ）。提供元の冪等キーは `unique(integration_account_ref, provider_idempotency_key)` を案とし、提供元側の保持期限が切れた後は冪等保証がないものとして扱う（結果不明からの再試行は許さない）。保持期限は能力定義の `describe_capabilities` で返す項目に入れる。

### T2-05（中）：作業中の取消の行を足す（Claude V2-03）

- 作業中の取消は状態を変えず `cancel_requested_at` を付けた「停止確認中」の表示にし、実行の停止を確認してから止まっているへ移す、と1行足す。チームで以前合意した方針と同じで、新しい決定ではない。
