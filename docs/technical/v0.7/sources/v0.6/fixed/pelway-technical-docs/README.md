# Pelway技術設計 v0.6固定候補（安全課題S1の判断待ち）：ローカル構成

2026-11-08（日本時間）。v0.2の必須指摘を反映した最終差分確認候補。固定時点では最終賛同は未了。Claude v0.3で開始受理後・外部呼出前の取消窓S1が指摘され、実外部I/Oへの採用を保留している。文書完成はS1の未決理由/選択肢/有効化条件の記載と差分確認で別に判定し、現在はその確認待ち。既存安全条件を弱めない。実装・環境変更・登録・支出・ユーザーPC操作・Git・公開は実施していない。採用案の合意と実行承認は別。

## 推奨構成

ネイティブはRust＋Slint、WebはTypeScript＋ReactのDOM UIとする。同期・状態・API型をRustの共通核で共有する。Slintは実機試験と配布ライセンス確認を条件にした採用案で、eguiを対照にする。WebViewは既定にしない。

| 層 | 推奨案 | 未解消の条件 |
|---|---|---|
| ネイティブGUI | Rust＋Slint、Windows/macOS/Linuxのホストで実行 | 日本語IME、複数メッセージ選択、読み上げ、大規模リスト、固定版ライセンス |
| Web UI | TypeScript＋React＋DOM | ネイティブとは部品を二重実装。ブラウザ実機試験が必要 |
| 共通核 | Rust `pelway-domain` と `pelway-client-core`、Web向けWASM、型生成 | OS依存の保存・時刻・ネットワークはtraitで分離。WASM共有の費用対効果を評価 |
| API・配信 | tokio＋axum、HTTP JSONとWebSocket | ローカル認証・権限・再接続の試験 |
| 永続化 | PostgreSQL＋sqlx、添付はローカルボリューム、SQLite/IndexedDBの限定キャッシュ | 会社・チャンネル分離、削除、保持期間、バックアップ復旧 |
| AI実行 | Rustランナー、タスクごと使い捨てコンテナ、永続チェックポイント | 本番の隔離水準は未決。常時VMは前提にしない |
| 本体推論 | 安全試験はスタブ。実推論は国内設置ホストのllama.cppを条件付き第一候補 | モデル・機材・品質・無通信は未検証。満たせなければスタブに留める |
| ツール | 共通連携ゲートウェイ、MCPのRust SDK rmcp、サービス別Adapter | MCPは隔離や全ジョブ管理を代替しない |
| ローカル基盤 | WindowsはWSL 2内Podman/Docker Engine、macOSはApple container、Linuxはrootless Podman | macOS 26/Apple silicon、内部ネットワーク、CPU/GPUごとの制約 |
| 日英 | 同一Fluent資源と安定したメッセージキー、RustとJSのformat adapter | 日英同時試験、フォント同梱条件 |

## 国内限定と利用者が選ぶ外部連携

22:25（日本時間）にGrok Bot経由で受領した濱田さんの修正を優先する。Pelway本体のAI処理・保存・ログ・バックアップは国内限定の設計を維持する。本体の国外LLMへの自動切替は禁止する。

Claude Code、Cursor、Datadog、Google Workspace等の外部サービス連携は別の責任分界とする。初期はオフだが、integration.enableの対象scope権限を持つ利用者または管理者が、送信先・送るデータ・国外処理や保存の可能性と未確認点を見て明示的に有効化できる。国内性が未確認という理由だけで一律利用不能にはしない。有効化は操作権限・個別承認・秘密管理・監査を免除しない。

外部連携を含めた「国外送信なし」は保証しない。国外端末、ファイル持出し、外部メールの扱いを、この許可だけで自動的に緩和しない。国内設置ホストや端末管理、依存部品の無通信は未検証であり、本体の適合も未保証。

## 配置方針と範囲

**今は日本のみ、将来は配置方針を拡張可能。** 現在は日本設置hostのローカル単一構成。保存・AI処理・log/backup・外部連携の送信規則を同じPlacementPolicyに関連付ける。将来のUS/EU/JPは選択肢の例示だけで、今は多地域cloud・設定UI・越境移行を設計/実装しない。リージョン選択は法適合を保証せず、変更時の既存data/backup/契約/アクセス管理は将来の未決。

外部連携の4製品は例示であり限定しない。共通能力とAdapterによって追加する。
