# 作業ログの定期キュレーション（2026-11-15）

Issue #308 に基づく初回の走査。位置づけは skill `command-team` の「改善ループ」の「定期キュレーション」、手順は runbook 12「作業ログの定期キュレーション」。

## 走査の範囲と方法

- 対象: `docs/worklogs/` 配下の全 worklog（`issue-*.md` の実装者メモ 59 ファイル、指揮役の巡回記録・判断の記録・改善点の表を持つ `*-conductor-substitute.md` 3 件、日付付きの設計・調査系 worklog、`backend.md`・`client.md`・`dev-infra.md` の担当別記録）。レビュー結果の記録は、実装者メモと巡回記録に引用されたレビュー指摘をたどる形で見た。
- 方法: 実装者メモの「詰まった箇所」「足りなかった情報・検証手段」「改善案」の全量抽出と、巡回記録の「改善点」「判断の記録」「改善点の表」の通読。候補は open Issue の一覧（2026-11-15 時点）と照合し、起票済み・反映済みのものは除いた。

## 候補の扱い

- C1〜C6 は正本の変更が要る候補。Issue 化を人間に提案する。キュレーション自体は正本を編集しない
- C5 は新規起票ではなく、open の Issue #218 の範囲確認（grep 採点の書き方規則を含めるか）として提案する
- C7〜C9 は待ちの再確認。C7 は次回のキュレーションで再評価する。C8・C9 は巡回の既存の仕組み（`needs-info`・ボードの Status）が見ているため、キュレーション側では動きがあるまで注記だけ残す
