# 社外に出る操作の承認は、個別の内容への承認と事前に決裁された型への承認のハイブリッドにする

ADR-0004の段階宣言の上に乗る拡張であり、ADR-0002で定めた固定承認の原則を、個別の内容から型へ拡張する。ADR-0002（承認者はカードの作成時に指定、期限切れは実行しない）とADR-0004（操作の4段階）の置き換えではない。読み取りと取り消せる内部の書き込みはADR-0004の既定の扱いのまま、取り消せない操作（削除・支払い・権限の変更）は型による自動化の対象外とし、従来どおり都度承認と承認者の限定を続ける。

## 決定

- **型**: 社外に出る操作のうち、事前に決裁された「型」に一致するものは自動実行してよい。型は、生成ルールとしてのテンプレート、宛先範囲、金額上限、データ範囲の組とする。型は版管理し、型の変更は内容の変更と同様に再決裁を要する。実行記録には、根拠となった型の版を結び付ける。
- **型の決裁者**: ADR-0002と同じ規則を使う。型の決裁カードの作成時に承認者（指名した1人か役割）を指定する。型にも期限を設け、期限が切れたら自動実行を止めて再決裁を求める（ADR-0002の「期限が切れたら実行しない」の原則を型へも適用する。期限の既定値は未決）。
- **一致判定**: 機械的検査（宛先ドメイン、金額、添付の有無、初めての宛先か）を先に行い、次に意味的な逸脱（過剰な約束、金額や契約条件への言及）の検査にモデル審査を使う。モデルは承認者ではなく番人であり、モデルの審査結果を承認とは扱わない。どちらかの検査に引っかかれば自動実行せず、都度承認へ落とす（fail-closed）。
- **事後統制**: 自動実行は全件を記録し、日次ダイジェストで承認者がまとめて確認できる。型ごとに即時停止でき、停止した型に一致する操作は都度承認へ戻る。
- **外部起点の実行**: メールやWebhookなど外部起点の実行は一段厳しく扱い、外部の文章に宛先や内容を決めさせない。型一致の判定は、Pelwayの中で組み立てられた内容に対して行い、外部の文面をそのまま判定の入力にしない。
- **学習の扱い**: 同じ都度承認の繰り返しから「型として自動化するか」の提案は出してよい。有効化は個人の蓄積ではなく、型定義への決裁で行う。逸脱や手直しの多い型は、降格（都度承認へ戻す）・一時停止を提案する。

## Considered Options

- **Always allow の個人蓄積（Rakazo式）**: 承認時に「常に許可」を選ぶと、以後の同じ操作を個人の設定として蓄積して自動化する方式。誰が何を許可したかが個人に散らばり、管理者が上限を決められず（ADR-0001の役割権限の上限と衝突する）、許可の変更や失効を版として追えないため採らない。
- **モデル審査のみによる自動化**: 機械的検査なしにモデルの判定だけで自動実行を許す方式。判定の根拠が機械的に検査できず、審査の失敗を機械の条件で抑えられないため採らない。モデルは番人であり、承認の根拠にしない。
- **全操作の都度承認の維持**: すべての社外操作を都度承認のままにする方式。定型の連絡まで毎回承認を求めると承認者の負担が積み上がり、ADR-0002の期限切れ停止と合わせて処理が滞るため採らない。ハイブリッドは、判定対象を機械的に限定した上で、承認の固定を個別の内容から型へ移すものである。

## Consequences

- `docs/decisions.md`、`docs/prd.md` §6・§7、`docs/technical.md` §3・§6、v0.7技術仕様の03・08（および10・11の該当文）は、このADRを参照する形に更新する。
- 監査ログには、自動実行の全件と根拠となった型の版を記録する。ADR-0007の`audit_events`への統合方法は実装課題とする。
- 未決として残すもの: 型の決裁の有効期間の既定値（ADR-0002の承認期限の長さと一緒に決める）、日次ダイジェストで承認者が異議を上げた場合の処理手順（社外に出た操作は巻き戻せない前提）。
- 型の定義・保存・一致判定・日次ダイジェスト・即時停止の実装は未実装であり、別Issueで行う。このADRは実装や実行許可の承認ではない。
