# テナントの分離にPostgreSQLのRow Level Securityを二重の守りとして加える

テナントの分離は、`workspace_id` の複合外部キーとアプリの絞り込みに加えて、PostgreSQLのRow Level Securityでも行う。接続またはトランザクションごとに現在の `workspace_id` を設定し、各テーブルのポリシーでその値に一致する行だけを読み書きできるようにする。アプリ側の絞り込みはそのまま残す。

複合外部キーは、別のワークスペースの行を参照することは防げるが、アプリが検索の条件を書き忘れた場合の漏えいは防げない。Pelwayは会社をまたぐ漏えいを最も重い事故として扱うので、アプリの誤りがあってもデータベースが行を返さない守りを足す。BullpenがSupabaseのRow Level Securityで同じ守りを置いている。

## Consequences

- 管理用の処理（移行、バックアップ、横断の運営作業）は、ポリシーを回避するロールを使う必要があり、そのロールの利用は監査の対象になる。
- 接続プールで `workspace_id` の設定を次の利用者に持ち越さないよう、トランザクション単位で設定する。
