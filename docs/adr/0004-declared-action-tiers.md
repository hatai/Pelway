# 操作の段階は連携ごとの宣言と管理者の確定で決め、決まっていない操作は止める

操作の4段階（読み取り、取り消せる内部の書き込み、外部、取り消せない操作）は、操作の名前やボタンのラベルから推測しない。連携ごとに、各操作の段階を宣言してもらう。MCPのツールのannotations（`readOnlyHint`、`destructiveHint` など）は手がかりとして管理者の画面に表示するが、段階は管理者が確定する。段階が決まっていない操作は「取り消せない操作」として扱い、止める。ワークスペースのルールはデータとして持ち、MVPではCELのようなルール言語は入れない。

名前やラベルから判定する方式（OpenBot）は、ラベルのないボタンなどを取りこぼすと提供元自身が書いている。annotationsは外部のサーバーが自分で申告する値なので、それだけで安全な段階に振り分けると、申告を偽るサーバーに承認を迂回される。決まっていないものを止める（fail closed）ほうを選ぶ。Slackbotも、種類が分からないツールを書き込みとして扱っている。
