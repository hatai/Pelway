# 承認者は承認カードの作成時に決め、期限が切れたら実行しない

承認カードを作るときに承認者を決める。承認者は、指名した1人か、役割（例：代表）のどちらかにする。依頼者が承認者を兼ねてよいかは、ワークスペースの設定で決める。承認カードには期限を設ける。期限が切れたら「期限切れ」の状態にして自動では実行せず、依頼者に知らせる。依頼者は承認者を変えられるが、変えた場合は新しい承認者にもう一度承認を求める。MVPでは、複数段の承認と「ワークスペースの誰でも承認できる」設定は作らない。

競合の多くは、承認できるのが依頼者本人だけ（Context、Grok Bot）か、誰でも承認できて最初の応答で処理が再開する（Rerun）。前者では依頼者と承認者を分けられず、後者では「誰の判断待ちか」が定まらない。Pelwayは依頼者とは別の人が判断する業務を対象にするので、承認者をカードに固定する。

## Consequences

- 承認APIは、承認する人の身元と、その人がカードの承認者であることを確かめる必要がある。
- `docs/technical/v0.7/body/08-decisions-open.md` のU06のうち、承認期限と複数承認者はこのADRで決まる。
