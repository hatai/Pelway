# 本体LLMは提供元のAPIをLLMゲートウェイ経由で使い、BYOKは契約者の責任で国内完結の例外とする

本体AIの推論は、国内ホストのローカル推論（llama.cppと事前取得モデル）ではなく、提供元がアクセストークンで提供するAPIを、LLMゲートウェイ経由で使う。ローカル推論の測定（Issue #95の旧内容）は行わない。

- テナントが自分で契約したAIを使う場合（BYOK）は、契約者の自己責任として国内完結の方針（10）の例外とする。開発中とMVPの実推論はBYOKだけで行う。
- 一般の利用者に提供する段階では、日本リージョンのある提供元（例: Google Vertex AIのasia-northeast1）をPelwayの既定にする。提供元の選定は別のIssueで行う。リージョン名だけでは国内完結の根拠にしない。Vertex AIの文書は、エンドポイントの指定がデータ所在や地域内処理を保証しないと述べている（[調査](../research/rust-llm-client-comparison.md)）。データ所在の条件と契約を選定で確かめる。

## BYOK

- 単位はテナント（会社）。テナントの管理者が設定し、そのテナントのすべてのBotに効く。
- 有効化は外部連携の許可（10 `integration_grant`）と同じ扱い。初期はオフ。管理者が説明を読んで明示的に有効にする。画面に「国内限定の外。提供元での保存と学習への利用は契約者の責任」と表示する。有効化と取消を監査に記録する。
- 使えるトークンは、提供元の規約でアプリからの呼び出しが認められているものに限る。例: Z.aiのGLM Coding Planの枠は対応するコーディングツール用で、自前のアプリやBotからの直接呼び出しは認められていない（[Z.ai Usage Policy](https://docs.z.ai/devpack/usage-policy)）。通常のAPIキーを使う。
- BYOKを有効にしたテナントでは、本体AIが扱う入力（会話、添付から取り出した文章、メモリ）をその提供元へ送る。資格情報や鍵などの秘密は送らない。
- 埋め込みもチャットと同じ提供元で作る。索引は「提供元とモデル」に結び付け、提供元を替えたら作り直す。
- ACPによる外部エージェント（Claude Code、Codex等）の接続も、BYOKと同じ例外の枠で扱う。LLMゲートウェイの実装（#95）の後に別Issueとする。

## LLMゲートウェイ

- 提供元の自動切替は行わない。BYOKの提供元からPelway既定の提供元への切替も行わない。提供元が使えないときは理由を表示して止める（10のD2・D12）。
- BYOKを設定していないテナントの本体AIはスタブのまま。Pelway既定の提供元は、選定が済むまで置かない。安全試験はスタブで行う。
- 利用量（トークン数と呼出し回数）をテナントごとに記録する。管理者は任意で上限を設定でき、上限に達したら止める。BYOKでも同じ。
- MVPでは応答をまとめて受け取る方式だけにする（streamingなし）。JSONスキーマを使う出力は、提供元を問わずPelway側で応答をスキーマ検証する。
- MVPのトークンは fnox の `PELWAY_LLM_API_KEY`（単一テナント）に置く。テナントごとの暗号化保存は別Issueとする。
- 提供元への接続には `rig-core` を使う。使う範囲はOpenAI互換エンドポイントのchat completionsとembeddingsだけで、エージェントやツールの機能は使わない。Pelway側にtraitを置き、rigはその内側に隠す。
  - HTTPクライアントはPelwayが作って渡す（`reqwest::retry::never()`、プロキシ、タイムアウトを設定）。rigの再試行判定は使わず、結果が不明な要求を自動で送り直さない（10のD3）。
  - トークンは要求ごとに取り出す。Vertex AIの1時間で切れるアクセストークンにも対応できる形にする。
  - rig-core 0.46のMSRVは1.97.1のため、Rustツールチェーンを上げる。
  - Z.aiの文書が `response_format` に挙げるのは `text` と `json_object` だけで、rigはZ.aiにも `json_schema` を送る。Z.aiが受け付けない場合は、Z.aiに限って `json_object` に切り替える。

## 測定

実装担当のネットワークはGitHubだけのため、実装担当はゲートウェイ、モックを使った試験、測定用のコマンドまでを作る。実際のAPIでの測定（合成データでの質、スキーマに合う割合、応答時間、費用）は、hataiが自分のトークンで実行し、結果を `docs/research/` に置く。対象は提供元ごとにチャット用1モデルと埋め込み用1モデル（Z.aiとOpenAI）。モデル名はコマンドの設定で指定する。

## Consequences

- 08のA7、03 §監査とローカル推論、10の場所・経路の台帳、02のLLM adapter・ローカルLLM・外部エージェントの行は、このADRを参照する形に改める。
- 本体の `core_domestic_policy` の外向き通信の既定拒否は変えない。BYOKの提供元への通信は、テナントごとの許可として限定proxyとゲートウェイを通す。
- ローカル推論（llama.cpp、日本語モデル、ruri-v3）は、国内完結の根拠が揃った提供元の一つとして、将来の選定で比べる候補に残る。
