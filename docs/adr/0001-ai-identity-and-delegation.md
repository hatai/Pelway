# AIは独立したメンバーとして、委ねられた権限と役割の権限が重なる範囲だけで動く

AIはPelwayの独立したメンバーで、操作の記録には「AI Xが依頼者Yに代わって実行」と残す。AIが動ける範囲は、依頼者が委ねた権限と、AIの役割で決めた権限が重なる部分に限る。役割の権限の上限はワークスペースの管理者が決める。依頼のたびに、依頼者の権限のうち上限の範囲内の部分を自動で委ねる。範囲を広げる操作は承認カードの対象にする。外部サービスの資格情報は、今までどおりgatewayの資格情報ブローカーが、タスクごとに範囲を絞った短命のトークンとして渡す。

依頼者の資格情報でそのまま動く方式（Context）や、AIが自分の身元を持たずメンバーとしてログインする方式（Grok Bot）では、「誰の判断で、誰の権限を使って実行したか」を記録で区別できない。Pelwayは依頼者・承認者・実行者を分けることを重視するので、AIに独立した身元を持たせる。

## Considered Options

- AIごとの鍵で全イベントに署名する方式（Buzz、Nostr）。身元の証明は強いが、利用者に鍵の管理を求めることになり、対象顧客の想定と合わないため採らない。
- 依頼者が、AIごとに常に委ねる範囲を自分で決めておく方式。設定の手間が依頼者ごとに散らばり、管理者が上限を把握できないため採らない。
