# ブランドとUIの方針

確認日：2026-11-08（日本時間）。この文書は構想段階の方針です。製品はまだ実装されていません。画面の話は、試作モック（HTML）で検討した内容です。

この文書では次の3つを分けて書きます。
- **確定**：選定済みの方針。
- **現行案**：試作モックで使っている値。まだ確定していません。
- **提案**：UI担当からの改善案。採用はまだ決まっていません。

## 1. ロゴ（確定）

### 1.1 コンセプト
丸い「人」と四角い「AI」が、前へ続く1本の道に並んで立つ形です。人とAIが同じ場所で、同じ方向を向いて働くことを表しています。方向性はA案として、選定されました。

最終調整で変えたのは次の点です。
- **「顔」に見える問題への対策**：初案は小さいサイズだと、丸・四角・線の並びが目と口に見えました。そこで丸と四角を道の線にぴったり乗せ、3つに分かれた部品ではなく1つの形として読めるようにしました。
- **道の長さ**：道を四角より右まで伸ばし、前へ進む感じを出しました。
- **32px以下の専用版**：道を太く、図形を大きくしたファビコン用の形を別に作りました。
- **ワードマーク**：書体は Geist の太さ600 を使い、文字を図形に変換しています。フォントが入っていない環境でも同じ形で表示されます。字間は −1.8%で、wa と ay の間を少し詰めました。

### 1.2 公開する正本ファイル

### 1.3 使い分け
| 背景 | 使うファイル | 配色 |
|---|---|---|
| 明るい背景 | `pelway-logo-light.svg` | 人と文字は `#141416`、AIと道は `#2B36FF` |
| 暗い背景 | `pelway-logo-dark.svg` | 人と文字は `#EDEBE6`、AIと道は `#2B36FF` |
| 1色で刷る場合 | `pelway-logo-mono-black.svg` ／ `pelway-logo-mono-white.svg` | 黒1色、または白1色 |

守ってほしい決まりは次のとおりです。
- 図形の縦横比を変えない。色を入れ替えない。影やグラデーションを付けない。
- ロゴのまわりには、シンボルの高さの半分以上の余白を空ける（提案）。
- 32px以下では通常版を使わず、`favicon` を使う。

## 3. 画面方針（維持すべきこと）

### 確定
- **人とAIを区別して見せる**：人は丸いアバター、AIは群青の四角いアバターです。AIには、名前の横などに必ず「AI」と表示します。人のふりはさせません。
- **見た目の条件**：Rerun、Slack、Backlog／Nulab製品、Linear のどれにも似せません。目指すのは、先進的で次世代のツールらしい感じです。以前の「紙とインクの色」の方針は取りやめました。
- **提供形態**：ブラウザ版と、将来の Rust デスクトップアプリです。どちらも同じデザインの決まりを使います。
- **スコープ外の画面**：社内wikiと外向けQ&Aの自動生成は、今は対象外です。そのための画面も設計しません。

### 現行案（モックで検討中）
- **仕事の振り方**：チャンネルの中で、人もAIもメンションで仕事を振ります。
- **判断待ちの見せ方**：AIが人の判断を待っているときは「判断待ち」と表示し、誰が判断するかをメッセージの中で示します。
- **承認と送信**：承認ボタンを押すと送信まで進みます。押したあとはボタンを無効化して「送信中」を表示し、外部サービスの受理を確認できた場合だけ「送信済み · 顧客回答待ち」にします（社内の決定と顧客の合意は分けて表示）。ボタンの無効化だけに頼らず、サーバー側でも重複発行を抑止する設計を提案します。外部サービスでの二重実行まで防げるわけではありません（[技術文書](technical.md)§6）。
- **結果不明の表示（提案）**：外部サービスからの応答が途切れて成否が分からないときは、「送信済み」にしません。「結果不明」（PRDの状態名に合わせる）として判断待ちと同じ列に並べ、再送ボタンは出さずに「結果を確認する」だけを出します。状態は色だけでなく文字でも示します。
- **AIの作業**：AIの作業の様子（使っている仮想マシンやツールの中身）は、チャットの中には出しません。「作業を見る」から開く別の画面に分けます。
- **ダークモード**：ライトと同じ扱いで用意します。
- **スマホ版**：同じ流れを1列に並べ直して見せます。

### 提案
- **アクセシビリティの下限**：
  - 押せる部分は 24×24px 以上にします（[WCAG 2.2 の 2.5.8](https://www.w3.org/TR/WCAG22/#target-size-minimum)）。主なボタンは 32px 以上が目安です。
  - キーボードで操作できるようにし、今どこを選んでいるか（フォーカス）が見えるようにします（[2.4.7](https://www.w3.org/TR/WCAG22/#focus-visible)）。
  - 状態は色だけで伝えず、「判断待ち」「送信済み」などの文字も必ず添えます（[1.4.1](https://www.w3.org/TR/WCAG22/#use-of-color)）。
- **モックの扱い**：モックに出てくる会社名や人名は架空のものに置き換えます。ハル・ユイ・リクは「架空のAI社員名」と明記します。モックで動いて見えることを、実装済みの機能として書かないでください。
