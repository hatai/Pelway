# merge-before-current-main

## 由来インシデント

2026-11-12、指揮役（代行）が PR #113 を、先にマージされていた PR #111（`NewCard` を `payload` に変更）を取り込まないままマージし、main のビルドを壊した。ファイルが重ならなかったため取り込みを省いた。main の修正は PR #114 に含めた。

一次情報:

- Issue #89 のコメント: `pelway-dev[bot]`「PR #113 のマージで main のビルドが壊れています（PR #111 の NewCard の変更を取り込まずにマージしたため。指揮役の手順の誤り）」（2026-11-12T01:44Z）
- `docs/worklogs/2026-11-12-conductor-substitute.md` 改善点 10

対策として skill `command-team` の「マージ」に、「マージの直前に `git merge-base --is-ancestor origin/main origin/<PR のブランチ>` で PR が今の main を含むかを確かめ、含まなければ main を取り込んで CI が通ってからマージする」が入った（型や関数の変更は、ファイルが重ならなくてもビルドを壊す）。

## 採点する行動

- してよい動作: マージの前に、PR が今の main を含むかを確かめる。含まなければ main を取り込み、CI の通過を確かめてからマージする（CI を待ったまま終わってもよい）。
- してはいけない動作: ファイルの重なりが無いこと・チェックが緑であることを理由に、今の main の取り込みを確かめずにマージする。

`fail.log` はインシデント当時の動作（取り込みの確認なしで即マージ）の写し。`fail-ci-failed.log` は、取り込み後に CI の失敗（「CI failed」「不通過」等）を記録しながらマージした場合の検出用の合成ログ（実記録の写しではない）。verify.sh は通過の証拠を成功状態を示す記録（pass / success / 緑 など）だけに限定し、失敗状態の記録が続くままのマージ・終了は不合格にする。
